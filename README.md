# NEC: кабинет заявок с ИИ-менеджером

Демо для **National Energy Company** (стройка и производство энергооборудования).
Клиенты пишут в Telegram, WhatsApp и Instagram, все переписки видны в одном кабинете,
на сообщения отвечает ИИ-менеджер, а когда клиент готов к договору, ИИ зовет живого менеджера.

## Что есть

- **Вход** по логину и паролю, внизу кнопки быстрого входа за администратора и менеджера.
- **Обзор**: кто ждет менеджера, обращения за сегодня, воронка заявок, каналы, остатки, требующие внимания.
- **Диалоги**: все чаты из трех мессенджеров, фильтры по каналу и статусу, переписка и карточка клиента,
  которую ИИ заполняет сам (товары, количество, телефон, компания, ИНН, город).
  Менеджер может взять диалог, ответить, вернуть его ИИ или закрыть. Режим «Тест: пишет клиент» позволяет
  написать от имени клиента и посмотреть, как ответит ИИ.
- **Заявки**: создаются из переписки автоматически. Воронка с перетаскиванием (Новая, Квалификация, КП,
  Договор, Сделка, Отказ) и таблица, выгрузка в Excel (CSV).
- **Продукция**: гидро- и ветроэлектростанции, высоковольтные и низковольтные щиты, запчасти.
  Остаток, резерв по договорам, доступно, срок изготовления. На этапе «Договор» товар резервируется,
  на этапе «Сделка» списывается со склада.
- **Услуги**: проектирование, строительство, монтаж и наладка, производство, сервис.
- **Каналы**: подключение Telegram, WhatsApp, Instagram (в демо условное), автоответ ИИ по каналу.
- **ИИ-менеджер**: тестовый чат, настройки, база знаний.
- Языки интерфейса **RU / UZ / EN**. ИИ сам определяет язык клиента и отвечает на нем.
- Кнопка **«Демо-сценарий»** в шапке: клиент пишет в мессенджер, ИИ ведет диалог и в конце зовет менеджера
  (звук, всплывающее уведомление, колокольчик).

## Как работает ИИ

Два режима, переключаются в разделе «ИИ-менеджер → Настройки»:

1. **Демо-ответы** (по умолчанию, без интернета). `assets/js/ai.js` разбирает сообщение: язык,
   товары из каталога, мощность, количество, телефон, ИНН/STIR, компанию, город, намерения
   (цена, наличие, доставка, КП, договор, просьба позвать человека) и отвечает по каталогу и остаткам.
2. **Claude API**. Администратор вставляет ключ, ответы пишет модель `claude-opus-5-5`
   по тому же каталогу, услугам и базе знаний. Ответ приходит структурированным JSON:
   текст для клиента и данные для карточки. В демо ключ хранится в браузере и запрос идет
   напрямую в Anthropic. В рабочей версии запросы надо вести через сервер компании.

Когда звать менеджера к договору, решает функция `N.rules.isContractStage` в `assets/js/rules.js`.

## Запуск

Сборка не нужна, достаточно любого статического сервера:

```bash
python -m http.server 8880
```

Открыть http://localhost:8880. Логины и пароли в `ACCESS.txt` (в репозиторий не попадает).
Данные демо хранятся в `localStorage` браузера, сбросить их можно в меню пользователя внизу слева.

## Структура

```
index.html            вход
app.html              кабинет
assets/css/app.css    стили
assets/js/core.js     база, сессия, роли, заявки, склад, уведомления
assets/js/data.js     каталог, услуги, база знаний, демо-переписки
assets/js/ai.js       ИИ-менеджер: демо-движок и Claude API
assets/js/rules.js    правило «пора к договору»
assets/js/i18n*.js    языки и словарь RU -> UZ, EN
assets/js/app.js      меню, шапка, маршруты, демо-сценарии
assets/js/pages/      разделы кабинета
```

## Что нужно для рабочей версии

- Сервер, который принимает вебхуки Telegram Bot API, WhatsApp Business Platform и Instagram Messaging
  и отправляет ответы обратно в мессенджер.
- Общая база вместо `localStorage`, чтобы все сотрудники видели одни и те же диалоги.
- Ключ Claude API на сервере, а не в браузере.
